# Validation of the first Mac-targeted project

Engine: Godot Standard `4.6.3.stable.official.7d41c59c4`.
Host: Linux x86_64; macOS was not available for execution.

## Completed

- Headless editor import completed successfully.
- `godot --headless --path . --script res://tests/smoke.gd`: 20 behavioral checks passed, exit 0. The suite uses real physics ticks for keyboard movement and collision, and exercises inventory, detection, paths, chunk streaming, protection, death and scene reload. Failures produce nonzero exit status.
- Actual OpenGL Compatibility rendering ran on Mesa llvmpipe with an Xorg dummy display and Dummy audio output. The engine compiled both custom shaders and rendered the scene and menus without shader/script errors. Captures are `title-screen.png` and `first-play.png` at 1280×720. V-sync was unavailable on the dummy display; this is a test-display limitation.
- Audio is generated by the application from oscillators and seeded noise. Audio output was not heard on physical speakers in this environment.
- The replay path was exercised and input mappings remain valid across scene reloads.
- No external packages, credentials, game assets, or export templates are required to open the project in Godot.

## Still requires MacBook testing

Real macOS startup, frame rate, mouse capture / trackpad comfort, perceived sound balance, and play balance. No native `.app`, Apple signing/notarization, Android export or on-device touch validation is claimed. Touch scaffolding is retained for the next phase. Generated architecture is intentionally repetitive in this first survival prototype; animation and visual polish are basic.

## Reproduce

In the project directory, using Godot 4.6.3:

```sh
godot --headless --path . --editor --import --quit
godot --headless --path . --script res://tests/smoke.gd
```

Optional capture with a graphical display:

```sh
godot --path . --audio-driver Dummy --script res://tests/render.gd
```

On a restricted Linux runner, first set XDG_DATA_HOME, XDG_CONFIG_HOME and XDG_CACHE_HOME to writable task-specific directories and create them. This is not necessary for a normal local Mac installation. No always-on service is required.
